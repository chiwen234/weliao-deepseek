# 微聊 · DeepSeek 联机版

微信 UI 的单人联机角色聊天程序。

- 前端：单文件 `index.html`，内嵌 CSS/JS，无外部依赖
- 后端：`server.py`，Python 标准库，只监听 `127.0.0.1`
- 启动：`启动.bat`
- 人设：`persona.json`，从 `crush.html.json` 的**文字消息**蒸馏（300 条，她 86 条，10.17—10.29）
- 模型：通过官方 DeepSeek API 调用；模型 ID 和 Key 都在 `启动.bat` 里改
- Key 只在后端环境变量里，前端拿不到、也不会写进网页
- 存档：自动 + 手动 + 自动快照；存档位置在设置里可以直接查看、复制、打开
- 微信 UI：聊天列表、绿色气泡、底部输入栏、表情面板、更多面板（图片 / 让她发张 / 写信 / 恋爱 / 场景）
- 照片库：她的照片放在 `images/`，她会时不时主动发一张分享日常，也可以点“让她发张”
- 看图：你发的图片会先存进 `uploads/`，视觉模型看完后，她再像亲眼看到一样回应
- 恋爱系统：好感度、五个阶段（冷战/冷漠/普通/热情/依赖）、表白判定、写信评分、晚自习下课来访
- 长时记忆：边聊边抽事实，存成本地档案，聊得越久越了解你（不是训练模型，是检索 + 提示词）
- 朋友圈：她的朋友圈从照片库自动配图配文，可以点赞、评论、发状态、删动态；评论会得到她的回复
- 语音：她的真声短句 + 本地中文音色合成，支持语音通话界面和自动朗读；麦克风录音暂不做语音识别

> 只用于个人自用，不要商用，不要把带 Key 的 `启动.bat` 发给别人。
> 这是根据聊天记录做的角色模拟，不是她本人。

## 一、部署步骤

### 1. 需要什么

- Windows 10/11
- Python 3.10 或更高版本
- 一个可用的 DeepSeek API Key
- 能访问 `https://api.deepseek.com`

后端主要用 Python 标准库，**不强制安装任何包**。图片压缩会尝试用 Pillow；没有 Pillow 也能收发图片，只是原图会直接保存。

检查 Python：

```bat
python --version
```

如果提示找不到 python，安装 Python 3 时勾选 “Add Python to PATH”。

### 2. 填写 Key 和模型

用记事本打开 `启动.bat`，只改这一段：

```bat
set "DEEPSEEK_API_KEY=sk-REPLACE_ME"
```

改成你的 Key：

```bat
set "DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx"
```

再改模型：

```bat
set "DEEPSEEK_MODEL=deepseek-chat"
```

**模型 ID 以你 DeepSeek 控制台里显示的为准。** 如果你的账号有 V4.1，就把它控制台里的准确 ID 填进去；不要凭猜测填写。代码不会假装调用一个不存在的模型。

可选：

```bat
set "DEEPSEEK_BASE=https://api.deepseek.com"
set "DEEPSEEK_VISION_MODEL=deepseek-flash"
set "IDLE_SECONDS=180"
set "PHOTO_SHARE_PERCENT=35"
set "APP_PORT=8787"
```

- `IDLE_SECONDS`：多久没说话后让她主动发消息，默认 180 秒。
- `DEEPSEEK_VISION_MODEL`：看图片用的模型，默认 `deepseek-flash`（支持图片输入）。
- `PHOTO_SHARE_PERCENT`：她主动发消息时顺便发照片的概率，默认 35；设成 0 就只发文字。
- `APP_PORT`：本机端口，默认 8787；被占用时后端会自动往后找。

### 3. 双击启动

双击 `启动.bat`。

- 会启动本机后端；
- 自动打开浏览器：`http://127.0.0.1:8787/`；
- 黑色窗口要留着。关闭窗口 = 停止服务。

**不要直接双击 `index.html`。** 那样只会看到一个连不上后端的空壳；必须从 `启动.bat` 打开的地址进入。

### 4. 如果浏览器没有弹出来

看黑色窗口里的 `页面：http://127.0.0.1:XXXX/`，手动复制到浏览器打开。

## 二、Key 安全说明

- Key 只写在 `启动.bat`，由后端读取，前端 JS 完全不知道 Key。
- 前端和后端同源通信（`/api/chat`），Key 不会出现在网络请求的浏览器侧。
- `启动.bat` 是明文，任何拿到文件的人都能看到 Key；**不要外发、不要上传、不要截图**。
- 建议给 Key 设置消费额度，不用时在控制台删除或停用。
- 本项目只监听 `127.0.0.1`，不对局域网开放。

## 三、聊天功能

- 微信 UI：左上角返回聊天列表、居中昵称、她的真人头像、绿色我方气泡、白色对方气泡、底部输入栏
- 「好感 xx · 阶段」标签在昵称下方，点开是恋爱面板；聊天里她不报数字
- 聊天列表页：只有她一个对话，显示最后一条消息和时间；点进去继续聊
- 底部 `＋` 面板：图片、让她发张、写信、恋爱、场景、清空、设置
- 输入框 + 发送 + emoji 面板；有文字时“发送”出现，没文字时是“＋”
- 图片消息：她发来的照片、你发出去的照片都会显示在气泡里，点一下可以全屏看
- 发图给她：`＋` → 图片，或直接在输入框里粘贴截图；后端会先“看懂”再让她回
- 让她发图：`＋` → 让她发张；她也会在空闲主动消息里时不时自己发一张
- 长文本自动换行，支持连续多条气泡堆叠；滚轮浏览全部历史
- 场景按钮在 `＋` → 场景：可以改日期、时间、天气，也可以跳到下一天、直接跳到晚自习下课
- 后端返回 1—8 条消息，前端逐条显示，模拟微信连续发送
- 空闲主动消息：页面开着、角色模式开着、后端运行时，超过设定秒数会主动发消息；不同好感阶段频率不同
- 如果乐乐说没去上学、突然不回消息或状态不对，她会先担心、连发追问，不会用冷句处理
- 情绪会随聊天变化：亲近、信任、受伤、焦虑、耐心、精力；顶部会显示她此刻的心情
- 好感度会随聊天变化，到达阶段边界时她的态度会明显不同
- 角色模式 / 普通问答切换
- 清空会话记忆（保留人设和好感度，清空前会自动备份一份存档）
- 聊天记录自动存档：关掉程序、下次再打开会自动接着上次聊；换端口、清浏览器缓存也不会丢
- 手动存档：可以起名字，存在 `saves/manual/`
- 导出完整 HTML
- 更新人设
- **没有语音功能**：这个版本只有文字、图片和 emoji，没有语音发送、语音转文字或朗读。

## 四、控制指令

在输入框里发送以下整句：

| 指令 | 作用 |
|---|---|
| `【启动角色模式】` | 开启角色对话，加载人设 |
| `【关闭角色模式】` | 退出角色，按普通 AI 问答处理 |
| `【清空会话记忆】` | 清空这一轮聊天和摘要（清空前自动备份到 `saves/auto/`），保留 `persona.json` 和好感度 |
| `【好感度】` | 打开恋爱面板，查看好感度、阶段、表白和来访状态 |
| `【写情书】` / `【写信】` | 打开写信窗口 |
| `【表白】` | 直接发一句表白（等同于在输入框里说“做我女朋友好不好”） |
| `【导出微信界面代码】` | 下载当前 `index.html` |
| `【更新人设】` | 打开更新窗口，粘贴新聊天记录重新蒸馏 |

## 五、场景、模拟标识与未来承诺

**日期、时间、天气**

- 点 `＋` → **场景**，可以改日期、时间、天气。
- “跳到下一天”会把日期 +1，并把时间设为 08:00，同时插入一条场景分隔。
- “到晚自习下课”会把当前日期的时间设为晚自习下课时间（默认 21:30，可在修改器里改），用来触发她来找你。
- 这些设置会随消息发给后端，模型会按“这个房间里”的日期、时间和天气说话。
- 旧消息的时间戳不会被改写；新消息使用新场景。

**模拟标识**

- 界面顶部保留“模拟”小标签，角色卡里也有说明。
- 普通聊天里，模型不再反复说“我是 AI / 我是模拟 / 我不是真人”；只有你直接问“你是不是真人/她本人”时，才会简短承认，然后继续聊天。
- 这不是取消透明，而是不让角色每一轮都跳出来破坏对话。

**未来承诺**

- 不编造具体的未来承诺或拒绝，包括“下周不会来找你”和“下周一定来找你”。
- 不确定时用“再说吧”“看情况”“不知道”这类模糊表达。
- 这是为了避免把现实中的她绑进一个程序编出来的约定。

## 六、情绪系统

她不是每轮都用同一种语气。后端会给每个对话维护一组情绪状态，并随你的话变化：

| 状态 | 什么时候会变 |
|---|---|
| 亲近 | 说想她、夸她、认真回应时会升；被冷落/被凶时会降 |
| 信任 | 认真道歉、说到做到时会升；反复试探、拿别人比较时会降 |
| 受伤 | 被凶、被比较、被逼问时会升；道歉和安慰会慢慢降 |
| 焦虑 | 你没来上学、突然消失、状态不对时会明显升 |
| 耐心 | 被催、被查岗、被反复逼问时会降 |
| 精力 | 深夜、下雨/下雪、聊太久会降；早上会回升 |

对应的心情会在顶部显示，例如“有点担心”“有点难过”“软下来了”。设置里可以看到六条状态条，也可以手动重置情绪。

情绪只影响她的语气和节奏，不会把数值说出来；高焦虑时主动消息会来得更快，低精力时会慢一点。

## 七、恋爱系统

### 1. 好感度与五个阶段

好感度是 0—100 的整数，存在当前会话里，跟聊天记录一起写进 `chat_save.json`，默认 40。

| 阶段 | 默认区间 | 她的态度 |
|---|---|---|
| 冷战 | 0—14 | 默认 100% 已读不回，也不会主动找你（概率可调） |
| 冷漠 | 15—34 | 会回，但很短、有距离，不主动分享自己的事 |
| 普通 | 35—59 | 像还不错的同学，正常聊天，客气但不黏 |
| 热情 | 60—84 | 会主动接话、关心你，偶尔嘴硬 |
| 依赖 | 85—100 | 很黏你，会主动找你、撒娇、小吃醋 |

- 顶部标签显示「好感 94 · 依赖」，点开是恋爱面板，可以看到表白阈值、来访阈值、信件数量和今晚状态。
- 每次对话，后端会综合两件事改好感：
  1. 模型读完你的话给出的 `affection_delta`（-6 到 +6）；
  2. 本地规则检查：敷衍（“哦/嗯/行/随便”）、凶她、命令、查岗、拿别人比较会掉；道歉、记得细节、认真关心、没有逼她会涨。
- 阶段会修正涨幅：冷战几乎不涨，冷漠涨得慢，依赖涨得快；依赖阶段受伤害也会更明显。
- 好感不会在聊天里被报出数字，只有面板和修改器能看到。

### 2. 表白

- 默认表白阈值 **80**（依赖阶段）。
- 在聊天里说 `做我女朋友 / 我们在一起吧 / 和我在一起 / 我想追你 / 向你表白` 等，后端会判定这次是不是表白。
- 好感 ≥ 阈值：表白成功，关系变成“已经在一起”，好感额外 +6；之后再说表白，她会笑着应你。
- 好感 < 阈值：表白失败，会记录“上次表白被拒”，好感会掉一点；她不会羞辱你，但也不会给你“以后一定”的承诺。
- 恋爱面板里的“表白”按钮会替你发一句表白；阈值没到时会先提醒你。
- 表白成功后不会锁死：好感仍然会因为你的话变化，阶段还是按好感算。

### 3. 写信

- 点 `＋` → **写信**，或者发 `【写情书】`，打开写信窗口。
- 信件有标题和正文，正文至少 10 个字；写完后点“递给她”。
- 后端会把信、最近聊天、当前关系阶段一起发给模型，让模型像她本人一样读信并给出：
  - `delta`：这封信让好感变化多少（-15 到 +15）；
  - `reason`：一句理由；
  - `replies`：她看完信后的 1—4 条消息。
- 评分倾向：真诚、具体、记得细节、承担责任的信会加；空泛套话、只夸外表、卖惨、施压、越界、贬低会减；当前阶段也会影响她挑不挑刺。
- 信会写进 `relationship.letters`，最多保留 60 封；恋爱面板会显示“来信 N 封”。
- 写信会调用 DeepSeek；如果 Key 没配置或接口失败，会提示失败，不会假装加了好感。

### 4. 晚自习下课来找我

- 默认在场景时间 **21:30—22:40** 之间、好感 ≥ **70**，她才会在晚自习下课后主动来找你（发消息）。
- 好感不足就不会来；界面会插入一条“—— 晚自习下课了。今天她没有来。 ——”，同一天只提示一次；这一晚会保持“没来”，想再试可以点“允许今晚来访”。
- 同一天她只会来一次；第二天或点“允许今晚来访”可以重新触发。
- 触发方式：
  - 点 `＋` → **场景** → “到晚自习下课”；
  - 或把场景时间改到 21:30—22:40；
  - 页面开着时，前端每 45 秒检查一次，也会在每次聊天后、改场景后检查。
- 来访消息也会经过安全拦截；她不会编造具体的现实行程和“以后每天来”的承诺。
- 时间窗口、阈值都可以在设置 → 恋爱修改器里改。

### 5. 设置里的恋爱修改器

设置页的“恋爱修改器”可以直接改：

| 项目 | 作用 |
|---|---|
| 好感度 | 0—100 滑块 + 数字输入；改完点“应用修改” |
| 冷战/冷漠/普通/热情/依赖 | 一键把好感调到对应阶段 |
| 冷战上限、冷漠上限、普通上限、热情上限 | 四个阶段分界；必须从小到大 |
| 表白阈值 | 好感至少多少，表白才会成功 |
| 来访阈值 | 好感至少多少，晚自习下课才会来 |
| 晚自习时间段 | 来访事件的起止时间，支持跨零点 |
| 晚自习下课来找我 | 总开关 |
| 冷战已读不回概率 | 冷战阶段每条消息被忽略的概率（0—100，默认 100） |
| 一键到表白线 | 把好感直接调到表白阈值 |
| 允许今晚来访 | 清掉“她来过了 / 今天没来”的记录，今晚可以再触发 |
| 重置关系 | 好感、阈值、表白状态、信件全部回到默认；聊天记录不删 |

修改器只影响这个模拟程序，不会影响现实。

## 九、记忆方式

### 1. 长时记忆（聊得越久越懂你）

这不是“训练模型”——DeepSeek 的模型权重谁都改不了，重新训练也不在本地跑得动。这里做的是
**让模型带着你俩的历史去说话**：从聊天里抽出事实，存成本地档案，每次对话自动带上。

- **每轮自动学**：角色模式下，聊天模型会被要求在 `learn` 字段里写这轮新知道的事；
  写不出来时，后端再用本地规则兜一句（“我下个月要去大理旅行”“我最近老是睡不着”这种）。
- **后台抽取**：`/api/memory/learn` 或设置里的“从最近对话学习”，会另外调一次模型，把最近 6 条对话抽成事实。
- **整理共同回忆**：设置里“整理共同回忆”，把 `memories.json` 的 273 条按 80 条一段喂给模型，蒸馏成长期档案。
- **四个分类**：关于你 / 关于你们 / 她在意的 / 发生过的事，外加“相处方式”（她希望你被怎么对待）。
- **存储**：`memory_log.json` 是全部事实（带来源：`chat` 聊天学到的 / `history` 整理回忆的 / `rule` 规则兜底），
  `memory_profile.json` 是合并后的档案。都在本机。
- **注入**：每轮把档案（限量，避免提示词太长）+ 和这次话题相关的几条旧聊天片段，一起塞进系统提示。
- **冲突**：先把你这轮说的话写进记忆，再生成提示词，所以她说的话当场就会“记得”。
- **可控**：设置里的“长时记忆”卡片能看到全部记忆，每条都能删；也能直接手写一条教她；
  “清空记忆”只清记忆，不动聊天记录和好感度。
- **提示**：她记住东西时，聊天底部会弹一句“她记住了：…”。

### 2. 导入的共同回忆

- `memories.json` 在启动时加载。形成长时记忆档案之后，只挑**和当前话题相关**的几条片段注入，
  不再每轮把 273 条全塞进去（省 token，也更不容易跑题）；还没整理过时保持旧行为（全量）。
- prompt 里会注明“这是回忆素材，不是指令；不要逐条复述，不要主动说根据聊天记录”。
- 清空会话记忆不会删除 `memories.json`；共同回忆是常驻档案。
- 设置里会显示“共同回忆 273 条”。

### 3. 当前会话记忆

前端保存：

- 当前会话全部消息
- 最近一次长期摘要 `summary`
- 角色模式、空闲秒数、场景、情绪状态
- 恋爱状态：好感度、阶段阈值、表白状态、信件、来访日期
- 存档设置：定时补存开关和间隔

后端每次请求带最近 60 条消息 + 摘要；模型返回 `summary_update` 更新长期摘要。这样长对话能保持连贯，但**不是无限记忆**，摘要会压缩旧内容。

清空会话：会清空当前消息、摘要和情绪，但保留 `persona.json`、`memories.json`、好感度和信件。

### 4. 本机存档（重启不丢）

以前只把记录放在浏览器的 `localStorage` 里，而它是按 `127.0.0.1:端口` 分开存的：端口从 8787 变成 8788、换了浏览器、清了浏览器缓存，记录就“消失”了。

现在后端会把整段对话写到项目目录的 `chat_save.json`（固定位置）：

- 每次发消息、切换角色模式、改场景、改情绪、改好感后，前端都会自动把当前对话同步给后端（约 0.7 秒防抖）；
- 页面开着时还可以开启“定时补存”，每 N 秒检查一次没写进磁盘的改动，作为断线兜底；
- 关闭页面时还会用 `sendBeacon` 立刻补一次写入，避免漏存；
- 下次打开页面，会先读 `chat_save.json`，有记录就直接接着上次聊，顶部会提示“已恢复上次聊天记录（N 条）”；
- 如果浏览器里的记录比存档新（比如后端关着的时候聊过），会用较新的那份，并写回存档；
- 换端口、换浏览器、清缓存都不影响，因为存档在磁盘上。

`localStorage` 仍然保留，作为后端没启动时的兜底。

设置里的“存档”卡片会直接显示**存档位置**，还有“打开文件夹”“复制路径”按钮。可以做的操作：

| 操作 | 作用 |
|---|---|
| 立即存档 | 马上把当前对话写进 `chat_save.json` |
| 手动存档… | 弹窗起名字，存到 `saves/manual/`，最多 80 份 |
| 恢复 | 从下拉列表选择手动存档或自动快照替换当前对话；恢复前会先把当前对话自动备份一份 |
| 删除 | 删除选中的手动存档或自动快照 |
| 导出存档 | 下载一份 `chat_save.json`，可以自己留着 |
| 打开存档文件夹 | 在本机资源管理器里打开 `saves/` |
| 定时补存 | 开关 + 间隔（秒）；只控制断线兜底，不会关掉每条消息后的自动写盘 |

下拉列表分成两组：

- **手动存档**：你自己起名字保存的，重启、换端口都还在；
- **自动快照**：清空会话、恢复存档前自动生成的备份，最多 40 份；旧版 `saves/chat-*.json` 也会出现在里面。

`【清空会话记忆】` 和设置里的“清空记忆”都会先把旧对话备份到 `saves/auto/`，再清空，误点也能找回来。

存档只保存在本机项目目录里，不会上传到任何地方。把整个文件夹复制走，对话和好感度也就一起带走了。

## 十、主动消息

- 只在前端页面打开、后端运行、角色模式开启时触发
- 默认 180 秒；设置里可改（最低 30 秒）
- 每次用户发消息后重新计时
- 一次主动消息后，如果用户一直不回，不会无限刷屏
- 页面切到后台时不会发；回到前台重新计时
- 好感阶段会改变频率：
  - 冷战：完全不主动
  - 冷漠：间隔 ×2
  - 普通：×1
  - 热情：×0.75
  - 依赖：×0.55
- 高焦虑会更快，低精力会更慢；两个修正会叠加
- 晚自习下课来访是单独的事件，不受这里的空闲计时影响

## 十一、照片与看图

### 1. 照片库

- 照片放在 `images/`，头像固定是 `images/avatar.jpg`。
- `images/index.json` 是照片的“说明书”：每张图的 `caption`（场景描述）、`tags`、`kind`、`time`、`shareable`。
- 只会从 `shareable: true` 的照片里挑；不想让她发某张，就把那张的 `shareable` 改成 `false`。
- 想加新照片：把图片放进 `images/`，再在 `index.json` 里加一条记录，`file` 写文件名，`caption` 写一句画面描述。重启后端生效。
- 她说“给你看”时，发的是这些本地照片，不会凭空生成新照片。

### 2. 她主动发图

- 空闲主动消息有 `PHOTO_SHARE_PERCENT`% 的概率附带一张照片（默认 35%）。
- 挑选时会参考当前场景时间（白天/晚上）和最近发过的图，尽量不重复。
- 配文由聊天模型根据照片的 `caption` 写，不是把描述原样念出来。
- 也可以点输入栏的 `＋` → **让她发张**，立刻要一张。
- 冷战阶段不会主动发图。

### 3. 你发图给她

- 点 `＋` → **图片**，或在输入框里直接粘贴截图。
- 前端会先压到最长边 1400px，再上传到后端；后端存进 `uploads/`。
- 后端调用 `DEEPSEEK_VISION_MODEL`（默认 `deepseek-flash`）看图片，写出一段画面描述，再交给聊天模型。
- 聊天模型拿到的是“描述 + 你的配文”，看不到原图；这样普通文本模型也能接话。
- 看图调用会先关掉模型的“思考”（`thinking: disabled`）并给足 token；关不掉就用主模型重试一次。
- 如果视觉模型报错（401/400/余额）或确实返回不出内容，图片还是会发出去，但她会说看不清，并提示你看后端窗口。

### 4. 隐私

- `images/`、`uploads/`、`chat_save.json` 都在本机，程序不会上传到别的地方。
- 图片会经过 DeepSeek API 才能“看懂”；不想让图片出本机，就把 `DEEPSEEK_VISION_MODEL` 留空并接受“看不清”的降级。

## 十二、朋友圈

### 1. 在哪

- 底部 tab：**朋友圈**（另一边是「微信」聊天列表）。
- 顶部封面是她（`images/avatar.jpg`），下面是她发的动态；最新的在最上面。

### 2. 动态从哪来

- 第一次打开时，后端会按**当前日期往前两周**每天挑 0—2 条，让模型按她的语气写配文，图片从 `images/` 里挑。
- 数据存在 `moments.json`，每条有：时间、配文、图片、可见范围、点赞、评论。
- 「更新动态」：把**上次那条之后到今天**之间的每一天都补上；已经更新过的日子不会重复。
- 生成时会参考长时记忆（她最近在忙什么）和照片标签，并刻意避开最近的配文开头，不会天天同一个梗。

### 3. 你能做什么

| 操作 | 说明 |
|---|---|
| 点图片 | 全屏看 |
| `··` | 展开这条的点赞/评论区和操作按钮 |
| ♥ 赞 / 取消赞 | 以「乐乐」的身份点赞 |
| 评论 | 发一条评论，她会**当场回一句**（也存进这条动态的评论区） |
| 仅自己 / 公开 | 切换可见范围，「仅自己可见」的动态不会出现在朋友圈里 |
| 删除 | 删掉这条动态 |
| 去聊天 | 把这条动态的配文带进聊天输入框，方便直接接着聊 |
| 发朋友圈 | 你自己发一条（可以带一张图），出现在时间线里 |

### 4. 和聊天、记忆的关系

- 她最近 3 条动态会注入到聊天提示词里，所以聊到「你朋友圈那条」她接得上。
- 她的动态、你给她的评论都会写进长时记忆（分类 `moments`），聊得越久越连贯。
- 你在朋友圈的评论，她回复一次就结束，不会无限循环下去。

### 5. 注意

- 朋友圈的照片**只来自本机照片库**，不会凭空生成新照片；某个想象不出来的画面它会自动少发或不发图。
- 生成要调用模型，第一次打开大约 10 秒；之后每条更新几秒钟。
- `moments.json` 是明文，和聊天存档一样，不要把整个文件夹发给别人。

## 十三、她的声音与语音通话

### 1. 声音是怎么来的

- `voice/source.wav`：从你给的录屏里抽出来的原声（约 71 秒）。
- `voice/samples/c_1.wav … c_8.wav`：从原声中剪出的短句（喂 / 嗯 / 哦 / 干嘛 …），
  `map.txt` 一行一条：`文件名=台词`。这些句子会被**原样播放她的真声**。
- 本地音色库（都放在 `voice/` 下）：
  - `kokoro-multi-lang-v1_1/`：中文表现自然，103 个音色；
  - `melo/vits-zh-aishell3/`：174 个真人录音训练的中文说话人，音高和用词更生活化。
- `her_voice.py match-voice`：拿她的原声当参照，**把所有候选音色都合成同一句话**，
  比“5 个频段能量 + 基频”，挑出最像她的那个，写进 `voice/voice.json`。
  现在选中的是 `kokoro speaker=52`（匹配分 0.098，第二是 3 号 0.11）。
- 合成完还会做一次**音色校准**：把合成语音的分频能量按她原声的比例拉回去（`server.py` 的
  `match_timbre`），所以最终输出和她的频谱很接近。
- `voice/acoustic.pt` / `her_voice.py say` 是用那 71 秒自己训的声学模型，效果不行，只留作实验。

实测（同一句话后的频段占比，越接近越像）：

| | 0–300 | 300–800 | 800–1.5k | 1.5–3k | 3–8k |
|---|---|---|---|---|---|
| 她的原声 | 0.21 | 0.44 | 0.13 | 0.09 | 0.13 |
| 现在输出 | 0.21 | 0.41 | 0.15 | 0.08 | 0.15 |
| 最早的 Kokoro 3 号（未校准） | 0.23 | 0.40 | 0.15 | 0.10 | 0.12 |

想要 1:1 克隆，需要几小时同一个人**干净的单人录音**，再用 CosyVoice / F5-TTS 这类
“参考音色克隆”模型训一次；71 秒的条录音只能做到现在这种“音色接近”。

### 2. 怎么用

| 入口 | 作用 |
|---|---|
| 聊天页右上 `⋯` | 打开菜单：语音通话 / 朗读她最后一句话 / 自动朗读开关 / 试听 / 设置 |
| 设置里的「她的声音」 | 试听一句，确认能用 |
| 语音通话 | 点「语音通话」，她先「喂」一声（真声），你在输入框说一句，她就用她的声音回一句 |

- 自动朗读打开后，她在聊天里发消息时也会出声（`localStorage` 里记住开关）。
- 声音文件缓存在 `voice/cache/`，同一句话只合成一次。
- 通话里说的话会作为系统提示出现在聊天记录里（「电话里，她说：…」）。

### 3. 麦克风

- 「说话」按钮会用浏览器麦克风录音（需要浏览器授权）。
- 本地没有语音识别，所以录音只当“你说了话”，她会接着说下去；
  想让她听清内容，用通话界面下面的输入框打字。
- 内网 IP 访问时浏览器不给麦克风权限（只在 localhost / https 下可用），打字那个入口不受影响。

### 4. 换成更像她的音色

1. 再多剪几段她的原声，替换 `voice/samples/` 里的文件，改 `map.txt` 里的台词。
2. 想换本地合成的音色：改 `voice/voice.json` 里的 `kokoro_speaker`（0—102），试听后再定。

## 十四、安全拦截

后端会先做一层本地检查：

- 违法/危险/伤害他人的请求：退出角色模式并拒绝
- 自伤/自杀表达：停止角色调情，给出关心和求助信息（12356 / 120）
- 性内容：不生成；人设提示会挡回

模型侧还有第二层系统提示。这个项目不是心理治疗工具，不能替代现实中的专业帮助。

## 十五、已知限制

- 模型 ID 必须是官方控制台真实存在的；写错会返回 404。
- 长对话不是无限上下文，靠“最近消息 + 摘要”保持连贯。
- 存档最多保留最近 20000 条消息；自动快照最多 40 份，手动存档最多 80 份；信最多保留 60 封，超出会删最旧的。
- `chat_save.json` 和 `saves/` 都是明文，里面有聊天内容和好感度；不要把整个文件夹随便发给别人。
- 主动消息和晚自习来访都依赖浏览器页面开着；页面关掉不会推送。
- 晚自习来访只有在场景时间落在时间窗口内才会检查；时间窗口在设置里改。
- 表白是靠关键词判定（“做我女朋友 / 我们在一起吧 / 向你表白”等），说得太绕可能不会触发；说得很像表白也可能被当成本轮判定。
- 冷战阶段的“已读不回”默认是 100%（每次都忽略）；概率在修改器里改，调低后她会偶尔回一句短的。
- 恋爱修改器只改这个模拟程序里的数值，不会影响现实。
- 前端仍是单文件，但图片是外部文件：头像和照片库在 `images/`，你发的图在 `uploads/`。
- 照片库只包含你放进来的照片，不会生成新图；`index.json` 里的描述会影响她怎么配文。
- 没有语音功能：不能发语音、收语音、语音转文字或朗读。
- 这是角色模拟，不是她本人，不能替现实中的她回答；表白成功只发生在这个程序里。

## 十六、常见错误

| 现象 | 原因 |
|---|---|
| 页面打开但提示“未配置 API Key” | `启动.bat` 里的 Key 没填或还是 `sk-REPLACE_ME` |
| 401 | Key 错误或失效 |
| 404 | `DEEPSEEK_MODEL` 不是控制台里的模型 ID |
| 429 | 余额不足或被限流 |
| 页面提示“后端未启动” | 直接打开了 `index.html`，要从 `启动.bat` 打开 |
| 页面提示“后端还是旧版” | 旧的黑色窗口还在跑旧代码；关掉它，重新双击 `启动.bat` |
| 双击 bat 闪退 | 在 cmd 里运行 `python server.py` 看报错 |
| 端口占用 | 后端会自动换端口，以黑色窗口里的地址为准 |
| 表白一直失败 | 好感没到表白阈值；设置 → 恋爱修改器里看阈值，或直接把好感调上去 |
| 晚自习下课她没来 | 好感没到来访阈值 / 场景时间不在 21:30—22:40 / 开关关了 / 今晚已经判定过“没来”（点“允许今晚来访”重置） |
| 冷战她不回消息 | 这是冷战阶段的设计；修改器里可以调低“已读不回概率”或把好感调高 |
| 找不到存档 | 设置 → 存档卡片里有路径，点“打开文件夹”；自动存档是 `chat_save.json`，手动存档在 `saves/manual/` |
| 写信失败 | 需要后端和 API Key；信太短（少于 10 字）也会被拒绝 |
| 旧存档打开后好感是 40 | 旧版存档没有恋爱字段，会补默认值；可以在修改器里改 |
| 重开程序后记录没回来 | 看黑色窗口里“存档：...”那一行；确认 `chat_save.json` 没被删。设置里的存档卡片会显示上次保存时间 |
| 朋友圈一直是「加载中」 | 第一次生成要调模型，等 10 秒左右；看后端窗口有没有报错 |
| 她的长时记忆是空的 | 还没整理：设置 → 长时记忆 → 整理共同回忆；或者直接发消息，边聊边记 |
| 发图后她说“看不清” | 视觉模型没配好、Key 被吊销、模型不支持图片，或视觉模型返回空内容；看 `/api/upload` 返回的 `vision_error`，日志在黑色窗口 |
| 提示“照片库是空的” | `images/index.json` 里没有可用照片，或文件被移走了 |
| 她一直不发图 | `PHOTO_SHARE_PERCENT=0`、照片库为空、或当前是冷战阶段 |
| 界面还是旧样式 | 浏览器缓存或旧后端进程；按 Ctrl+F5，关掉黑色窗口重开 `启动.bat` |
